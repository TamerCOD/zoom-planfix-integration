## Шаг 1: Zoom API

### 1.1 Создание Server-to-Server OAuth приложения

1. Перейти на [marketplace.zoom.us](https://marketplace.zoom.us)
2. Нажать **Develop → Build App**
3. Выбрать тип **Server-to-Server OAuth** → Create
4. Заполнить:
   - **App Name**: PlanFix Integration
   - **Company Name**: Ваша компания
5. Перейти на вкладку **Scopes** и добавить:
   - `meeting:write:admin`
   - `meeting:read:admin`
   - `meeting:delete:admin`
6. Нажать **Activate**
7. Скопировать:
   - **Account ID**
   - **Client ID**
   - **Client Secret**

> ⚠️ **Важно**: JWT-токены Zoom устарели и отключены. Используйте только Server-to-Server OAuth.

## Шаг 2: Статусы задач в PlanFix

### 2.1 Статусы основной задачи

Перейти: **Управление аккаунтом → Задачи → Статусы задач → Добавить статус**

Создать 4 статуса:

| Название | Цвет | Тип |
|----------|------|-----|
| 🆕 Новая | Серый | Открытый |
| 🔵 Актуальная | Синий | Открытый |
| ✅ Завершённая | Зелёный | Закрытый |
| 🚫 Отменённая | Красный | Закрытый |

### 2.2 Статусы RSVP-подзадач

Создать ещё 3 статуса для подтверждения участия:

| Название | Цвет | Тип |
|----------|------|-----|
| ⏳ Ожидаем ответа | Жёлтый | Открытый |
| ✅ Буду | Зелёный | Закрытый |
| ❌ Не буду | Красный | Закрытый |

> 💡 После создания запустите `python setup_helper.py` для получения ID статусов.

## Шаг 3: Кастомные поля задачи

Перейти: **Управление аккаунтом → Поля → Добавить поле для задач**

Создать 4 поля:

| Название | Тип | Видимость | Назначение |
|----------|-----|-----------|------------|
| Zoom Meeting ID | Строка | Только чтение | ID встречи Zoom |
| Zoom Ссылка | URL | Только чтение | Ссылка для подключения |
| Zoom Пароль | Строка | Только чтение | Пароль встречи |
| Zoom UUID | Строка | Скрытое | Технический UUID (для API) |

> 📌 Поля "Только чтение" нельзя редактировать вручную — они заполняются автоматически.

## Шаг 4: Шаблон задачи "Конференция ZOOM"

Перейти: **Управление аккаунтом → Задачи → Шаблоны задач → Создать шаблон**

### 4.1 Основные настройки шаблона

- **Название шаблона**: Конференция ZOOM
- **Иконка**: 🎥 (или любая подходящая)
- **Начальный статус**: Новая

### 4.2 Поля шаблона (настроить видимость)

Включить и сделать **обязательными**:
- ✅ Название задачи
- ✅ Дата и время начала (dateBegin)
- ✅ Дата и время окончания (dateEnd)
- ✅ Исполнители/Участники

Включить (необязательные):
- ✅ Описание / Повестка встречи
- ✅ Zoom Meeting ID (только чтение)
- ✅ Zoom Ссылка (только чтение)
- ✅ Zoom Пароль (только чтение)

Скрыть или убрать лишние поля.

### 4.3 Процесс (Автоматизация)

В настройках шаблона → **Процесс** → создать новый процесс "Конференция ZOOM".  
Автоматизации добавим в следующем шаге.

## Шаг 5: Автоматизации PlanFix

Перейти: **Управление аккаунтом → Автоматизация → Создать сценарий**

### Сценарий 1: Задача создана → создать Zoom встречу

**Триггер**: Задача создана  
**Условие**: Шаблон задачи = "Конференция ZOOM"  
**Действие**: Выполнить HTTP-запрос

```
Метод: POST
URL: https://YOUR_SERVER/webhook/planfix
Заголовки:
  Content-Type: application/json
Тело запроса:
{
  "event": "task.created",
  "task_id": {{task.id}}
}
```

---

### Сценарий 2: Статус → Отменённая → удалить встречу Zoom

**Триггер**: Задача изменена  
**Условие**: Статус задачи = "Отменённая"  
**Действие**: Выполнить HTTP-запрос

```
Метод: POST
URL: https://YOUR_SERVER/webhook/planfix
Тело:
{
  "event": "task.cancelled",
  "task_id": {{task.id}}
}
```

---

### Сценарий 3: Статус → Завершённая

**Триггер**: Задача изменена  
**Условие**: Статус задачи = "Завершённая"  
**Действие**: Выполнить HTTP-запрос

```
Метод: POST
URL: https://YOUR_SERVER/webhook/planfix
Тело:
{
  "event": "task.completed",
  "task_id": {{task.id}}
}
```

---

### Сценарий 4: Изменение времени или участников

**Триггер**: Задача изменена  
**Условие**: Шаблон задачи = "Конференция ZOOM"  
**Действие**: Выполнить HTTP-запрос

```
Метод: POST
URL: https://YOUR_SERVER/webhook/planfix
Тело:
{
  "event": "task.updated",
  "task_id": {{task.id}},
  "status_id": {{task.status.id}},
  "changed_fields": "dateBegin,dateEnd,assignees,name"
}
```

> 💡 **Примечание по переменным PlanFix**: точный синтаксис переменных (макросов) зависит от версии PlanFix. В поле "Тело запроса" используйте кнопку **"Вставить переменную"** рядом с полем для выбора доступных макросов.

## Шаг 6: Календарь в Планировщике

### 6.1 Настройка представления

1. Перейти в **Планировщик** (левое меню)
2. Нажать **+** для добавления нового представления
3. Выбрать **Календарь**
4. Настроить фильтр:
   - **Фильтр по шаблону**: Конференция ZOOM
   - **Отображать дату**: Дата начала задачи
5. Назвать представление: **📅 Конференции Zoom**

### 6.2 Дополнительные настройки отображения

В настройках календаря:
- **Цвет событий**: по статусу
  - Новая → серый
  - Актуальная → синий
  - Завершённая → зелёный
  - Отменённая → красный
- **Показывать в описании**: Zoom Ссылка
- **Период**: Месяц / Неделя (по вашему предпочтению)

## Шаг 7: Развёртывание сервера

Выберите один из вариантов:

### Вариант A: Railway.app (рекомендуется — быстро и бесплатно)

```bash
# 1. Установить Railway CLI
npm i -g @railway/cli

# 2. Войти
railway login

# 3. Инициализировать проект
cd zoom-planfix-integration
railway init

# 4. Задать переменные окружения (из .env файла)
railway variables set PLANFIX_ACCOUNT=mycompany
railway variables set PLANFIX_TOKEN=xxx
railway variables set ZOOM_ACCOUNT_ID=xxx
# ... и остальные переменные

# 5. Задеплоить
railway up

# 6. Получить URL
railway domain
# Результат: https://zoom-planfix-xxxxx.up.railway.app
```

### Вариант B: VPS с Docker

```bash
# На сервере:
git clone <your_repo> zoom-planfix
cd zoom-planfix

# Создать .env из примера
cp .env.example .env
nano .env  # заполнить все значения

# Запустить
docker-compose up -d

# Проверить логи
docker-compose logs -f

# URL будет: http://YOUR_VPS_IP:8000
# Рекомендуется настроить nginx + SSL (Let's Encrypt)
```

### Вариант C: Локально (только для тестирования)

```bash
# Установить зависимости
pip install -r requirements.txt

# Создать .env
cp .env.example .env
# Заполнить .env...

# Запустить
uvicorn webhook_server:app --reload --port 8000

# Для тестирования из интернета — ngrok:
ngrok http 8000
# Получите URL вида: https://xxxx.ngrok.io
```

> ⚠️ **Важно**: Webhook-сервер должен быть доступен по HTTPS из интернета.  
> PlanFix отправляет запросы только на HTTPS адреса.

## Тестирование

### Проверка сервера

```bash
# Healthcheck
curl https://YOUR_SERVER/webhook/planfix/../health
# Должен вернуть: {"status":"ok"}
```

### Проверка PlanFix-подключения

```bash
python setup_helper.py
# Должен вывести списки статусов, полей, шаблонов
```

### Тест создания задачи

1. Создать задачу в PlanFix с шаблоном **"Конференция ZOOM"**
2. Указать название (станет темой Zoom)
3. Указать дату начала и окончания
4. Добавить исполнителей (участников)
5. Сохранить

**Ожидаемый результат**:
- В задаче появится комментарий со ссылкой на Zoom
- Заполнятся поля "Zoom Meeting ID", "Zoom Ссылка", "Zoom Пароль"
- Для каждого участника появится подзадача "✋ [Имя] — подтвердите участие"
- Статус задачи изменится на "Актуальная"

### Тест отмены

1. Изменить статус задачи на "Отменённая"
2. **Ожидаемый результат**: встреча удалится из Zoom, появится комментарий

### Тест RSVP

1. Открыть подзадачу со своим именем
2. Изменить статус на "Буду" или "Не буду"
3. Другие участники не смогут изменить вашу подзадачу (только свою)

## Часто задаваемые вопросы

**Q: PlanFix не отправляет webhook**  
A: Проверьте HTTPS на сервере. PlanFix поддерживает только HTTPS-адреса.

**Q: Zoom говорит "Invalid access token"**  
A: Убедитесь, что приложение Zoom активировано (кнопка Activate в marketplace.zoom.us).

**Q: Подзадачи RSVP не создаются**  
A: Проверьте, что в задаче есть исполнители/участники. Без участников подзадачи не создаются.

**Q: Встреча создаётся на неправильное время**  
A: Проверьте настройку ZOOM_TIMEZONE в .env. По умолчанию Europe/Moscow.

**Q: Как настроить участника, который не исполнитель?**  
A: В PlanFix добавьте сотрудника как "Аудитора" или "Наблюдателя" задачи — сервер автоматически создаст для него RSVP-подзадачу.
